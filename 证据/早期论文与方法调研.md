## 1. 结论先行

1. **本题是 18 类来源归因，不是 AI/人类二分类。** 论文中 DetectGPT、Fast-DetectGPT、Binoculars、RAID、MAGE、M4、MULTITuDE、MultiSocial 等的 AUROC/F1/TPR@FPR，大多回答“是不是机器生成”，不能直接代表“是哪一个模型”。它们最有价值的部分是概率/秩统计特征、短文本/OOD 压力测试和分组验证设计。
2. **验证必须按 `prompt_id` 分组。** 训练数据 2,699 行、150 个 prompt、18 个标签；149 个 prompt 有 18 行，1 个 prompt 有 17 行；没有 `prompt_id × model` 重复。随机按行切分会把同一题的其他模型回答放进训练集，产生主题泄漏。
3. **当前最可信的工程起点是 style-aware TF-IDF + LinearSVC。** 工作区 Kaggle 源码在 5 折 `GroupKFold(prompt_id)` 中报告 pooled OOF balanced accuracy 约 **0.384484**；该数值应视为公共 notebook 的可复现锚点，但因为配方在同一开发折上比较过，仍有选择乐观，不能当隐藏测试保证。
4. **本地新跑的依赖轻量诊断基线为 0.273373；随后已成功复现 style-aware LinearSVC。** 纯 Python hashed char/word + 类中心余弦基线严格按 prompt 分组，不能和 LinearSVC 直接横比。补齐依赖导入兼容层后，四路 style-aware TF-IDF + `LinearSVC(C=0.5)` 的本地 pooled OOF BA 为 **0.3844842158**，与 notebook 历史值完全一致；这仍是同一开发折选择过的配方，不是隐藏测试保证。另已提供 full-train 独立推理脚本和可回读校验的 `submission.parquet`。
5. **prompt recovery / Hungarian assignment 默认关闭。** 训练结构很诱人，但已有历史记录显示 independent OOF/LB 约 0.327/0.336，recovered assignment OOF/LB 约 0.419/0.308，复杂版本 OOF/LB 约 0.501/0.351。高 OOF 没有稳定转化为隐藏测试，说明测试批次可能不是每个 prompt 恰好一次各模型。
6. **最有希望的提升方向是三条分支的受控融合：**
   - 原文字符/词/结构指纹：style-aware TF-IDF、LinearSVC；
   - 冻结或轻量微调 encoder：DeBERTa-v3 / LUAR / Style-Embeddings，先只做 prompt-grouped OOF；
   - 可获得 logits 的开放参考模型统计：NLL、log-rank、Fast-DetectGPT/Binoculars 比值，作为附加特征。  
     所有权重、阈值、中心化策略和家族 gate 都必须在 outer train 内的 inner grouped CV 选择。

## 6. 推荐的可实施方案

### 方案 A：稳定 CPU 提交（P0，建议先做）

**结构**：style-aware TF-IDF + LinearSVC；默认逐条独立预测。  
**特征**：

- raw char 3–5，最多 250k；
- word/punctuation 1–3，最多 180k，权重 0.7；
- shape char 2–6，最多 60k，权重 0.5；
- function-word/punctuation 1–3，最多 50k，权重 0.5；
- `min_df=2`, `sublinear_tf=True`, `lowercase=False`，保留 Unicode、大小写、空白、标点；`LinearSVC(C=.5,max_iter=4000)`。

**验证**：一次冻结 5 折 `GroupKFold(prompt_id)`；如果要比较权重/范围，用 outer 5-fold + inner 3-fold。  
**提交**：full train fit，test 只 transform，生成两列 `id,model` Parquet。  
**优点**：速度快、依赖少、可解释、容易交付。  
**缺点**：可能学习主题和固定回答模板；同族版本易混淆。

### 方案 B：CPU 统计概率特征 + 监督融合（P1，性价比最高的研究方向）

**结构**：方案 A 的 logits/margins + Ghostbuster/DetectLLM/Fast-DetectGPT 风格统计特征。  
**特征候选**：

- 1–3 个本地开放参考 LM 的平均 NLL、token NLL 方差、长度归一化 NLL；
- log-rank、top-1/top-5/top-10 质量比例；
- 参考模型间的 PPL 差、cross-PPL、Binoculars 比值；
- 前缀/句子/窗口的均值、分位数和极值；
- 方案 A 的各类 decision margin 和 provider/family 辅助 score。

**注意**：只有本地可加载且许可可用的参考模型才可用；闭源目标模型不能直接取 logits。所有统计特征在每个 fold 只使用训练集 fit 的 scaler/分类器。Fast-DetectGPT 的条件曲率只作为特征，不把 AI-detection score 当身份概率。

**模型**：正则 logistic/线性 SVM/小型 GBDT；权重由 inner OOF 拟合，外层只评一次。  
**优点**：对应多篇论文且不必训练大模型。  
**缺点**：需要 logits、tokenizer 对齐；短文本估计噪声大，必须实测增益。

### 方案 C：冻结 encoder + 轻量监督 head（P1/P2）

**结构**：DeBERTa-v3-base、LUAR 或 Style-Embeddings 的冻结 embedding + 18 类线性/MLP；再与方案 A 做 OOF 融合。若冻结效果不足，再只对 encoder 最后若干层或分类头做 LoRA。  
**辅助任务**：provider/family 分类；同 prompt 异模型作为困难负例；同模型跨 prompt 作为正例。  
**验证**：outer prompt-grouped OOF；pair/triplet 必须在 outer train 内构造，不能先全数据配对。  
**优点**：有机会补上字符模型对长距离结构/语义风格的盲点。  
**缺点**：小样本过拟合、权重/模型下载和离线重跑约束；不能依据论文作者分数推算本赛成绩。

### 方案 D：Qwen/LoRA/center 的竞赛级重模型（P2，资源足够时）

只在 A/B/C 已固定后做，不直接复制 v20 全栈。逐项加入：

1. plain Qwen/DeBERTa head；
2. prompt-center twin；
3. family gate；
4. Sinkhorn/类边际校准；
5. extra data。

每一步需保存 outer OOF logits、模型/数据 hash、GPU/时间、inner 选择记录。默认关闭“每隐藏 prompt 一次一个模型”的 assignment。测试聚类/中心化必须用已知 prompt 组成的伪 test batch 做 transductive CV 模拟，不能把对真实 hidden test 的聚类当普通验证。

### 方案 E：不推荐的默认方案

- prompt recovery + Hungarian 强制每组标签不重复；
- 全量 train/test 联合拟合后直接报告 CV；
- 用另一个 LLM 改写训练文本并保留原模型标签；
- 把二分类 detector 的 AUROC/F1 当 18 类 identity accuracy；
- 依赖未经核实的 public LB 注释、版本分数或外部 checkpoint；
- 用 test batch 类配额/Sinkhorn 代替监督模型的真实校准。

## 7. 推荐执行顺序与验收标准

### P0

1. 固定 [`verified_data_audit.json`](evidence/verified_data_audit.json) 和 train SHA；冻结 5 折 prompt split。
2. 运行/复核 style-aware 四视图；保存 pooled OOF、fold BA、per-class recall、confusion、macro-F1。
3. 补跑官方 LR、裸 TF-IDF/SVM 的同一 grouped CV；裸脚本标题分数不作为结果。
4. 生成 full-train `submission.parquet`，回读验证列、顺序、ID、标签。

### P1

1. 预注册 shape/function/stylometry/类权重小消融；outer train 内 inner CV 选参数。
2. 加入短文本长度切片、provider/family 错误矩阵和 prompt-level bootstrap CI。
3. 只在有可加载开放 LM 时加入 NLL/log-rank/Binoculars 特征；保存特征矩阵和模型 hash。
4. 冻结 encoder/LoRA 与字符分支做 OOF 融合；不重复利用同一 OOF 调权。

### P2/P3

1. 对 center/transductive/extra data/assignment 做独立伪 test 压力测试；只有多个固定 holdout 均不劣才入提交。
2. 记录外部数据许可证、生成配置、prompt overlap 和来源 hash；否则不使用。

验收：

- 每个 fold 与验证 prompt 完全无交集；
- vectorizer/scaler/SVD/权重只在训练 fold fit；
- 所有模型选择在 inner CV；
- 结果中区分本地实跑、公开 notebook OOF、作者历史 LB、论文原始数字；
- 最终提交仅 `id,model`，且可由离线环境从代码和固定输入重建。

## 9. 最终判断

如果目标是**现在就提交一个稳健、可解释、能在离线评分重跑的版本**：先用方案 A，严格按 prompt-grouped OOF 固定一次，关闭 prompt recovery、Hungarian、Sinkhorn 和未经验证的 test center。  
如果还有 GPU/时间：优先做方案 C 的冻结 encoder 与方案 B 的开放 LM 概率特征，采用 nested grouped CV 融合。  
只有在保存了完整 OOF logits、伪 test transductive 验证和资源/许可清单后，才考虑方案 D。论文调研的主结论不是“某篇论文保证高分”，而是：**主题混淆、短文本、未知 prompt、版本近邻和二分类指标误读，是这个比赛的主要失败来源；字符指纹 + 严格分组验证 + 受控多分支融合，是最可验证的路线。**
